## The problem

A model that says "sell" is not much use to the person who has to decide. They need to know what pushed it there, and whether that reason makes sense. Our final degree project at the Complutense was a decision-support system for investors: an MLP classifier recommends buy, hold or sell, and every recommendation comes with its reasons.

The team built the data, the model and the interface together. My part was the explanation layer, plus the first version of the data layer in Supabase and a share of the architecture and model integration.

## What I built

`MLPShapExplainer`, a Python component that takes a prediction from the classifier and returns the contribution of each input feature to it, using SHAP. It sits inside the prediction workflow, so the frontend receives the recommendation and its explanation in one response and can draw them side by side.

## Three decisions that mattered

**Background data from the right moment.** SHAP measures each feature against a reference sample of data. In a time series, a careless reference can include data from after the day being explained, which quietly lets the future into the explanation. The explainer builds its background only from data that was consistent in time with the prediction.

**Build once, explain many times.** Building a SHAP explainer is the expensive part; asking it about one prediction is cheap. The explainer is cached, so explaining a new recommendation does not mean paying the set-up cost again.

**Numbers a person can read.** Raw SHAP output is a matrix: one value per feature for each of the three classes. The layer turns it into a short ranked list of contributions towards the recommended action, named in terms of the original features, which is what the interface shows.

## Result

The project was graded 9.7 out of 10. More useful to me: it taught me that an explanation is a product feature with its own correctness problems, not a chart added at the end.

## What I would do next

Measure the explanations themselves: how stable they are when the input barely changes, and whether removing the top features really moves the prediction. Then let a language model write the explanation in plain words, checked against the SHAP values so it cannot invent a reason. That is the credit project I am building now.
